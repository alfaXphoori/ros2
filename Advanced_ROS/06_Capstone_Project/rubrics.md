# 📊 เกณฑ์การประเมินผลโครงงานบูรณาการ (Capstone Project Rubrics)

---

## 📐 สัดส่วนการให้คะแนน 5 มิติ (Total: 100 คะแนน)

| มิติการประเมิน (Dimension) | น้ำหนัก | วัตถุประสงค์เชิงพฤติกรรม |
|---|:---:|---|
| **1. ROS 2 Core & Communication Architecture** | **20%** | ความถูกต้องในการออกแบบ Node, Topics, Services, Actions, Parameters, และ QoS |
| **2. Robot Kinematics & Gazebo Simulation** | **20%** | โมเดล URDF/Xacro, ความถูกต้องตาม REP 103/105, การจำลองฟิสิกส์และการต่อ `ros_gz_bridge` |
| **3. 2D SLAM Mapping & Map Quality** | **20%** | ความสมบูรณ์ของแผนที่ ไม่เบี้ยว ไม่ซ้อน (Loop Closure แม่นยำ) และสัดส่วนมาตราส่วนถูกต้อง |
| **4. Nav2 Stack Autonomy & Waypoint Patrol** | **25%** | ความแม่นยำในการเข้าจอด (Goal Tolerance), การหลบสิ่งกีดขวาง และการปฏิบัติภารกิจครบวงรอบ |
| **5. Code Quality, Standards & Documentation** | **15%** | มาตรฐานโค้ด PEP 8, ระบบ Launch System, Logging ชัดเจน และเอกสารรายงานทางเทคนิค |

---

## 🏆 ระดับคะแนนและการประเมิน (Performance Levels)

- **ดีเยี่ยม (Distinction: 85 - 100%):**  
  ระบบทำงานอัตโนมัติครบถ้วนสมบูรณ์ 100%, หุ่นยนต์หลบหลีกสิ่งกีดขวางแบบพลวัตได้นุ่มนวล, แผนที่ SLAM มี Loop Closure แนบสนิท, โค้ดมีการจัดการ Exception และ Lifecycle Management ครบครัน
- **ดี (Proficient: 70 - 84%):**  
  ปฏิบัติงานสำเร็จตามโจทย์หลัก, เดินทางถึงทุกสถานีตรวจได้, แผนที่ถูกต้องชัดเจน, อาจมีจังหวะสะดุดหรือชะงักระหว่างหลบสิ่งกีดขวางเล็กน้อย
- **พอใช้ (Developing: 50 - 69%):**  
  ระบบรันได้ แต่มีจุดที่ต้อง Restart มือ, การนำทางพลาดบางจุดตรวจ หรือเกิดการชนกับขอบชั้นวางเนื่องจาก Costmap Inflation แคบเกินไป
- **ต้องปรับปรุง (Unsatisfactory: < 50%):**  
  ไม่สามารถ Spawn หุ่นยนต์เข้าสู่ Gazebo ได้ หรือโหนด Nav2 ไม่สามารถเชื่อมต่อกับ Topic ของเซนเซอร์ได้
