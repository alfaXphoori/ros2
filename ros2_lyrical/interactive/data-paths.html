เส้นทางข้อมูล ROS 2 Lyrical

เลือกรูปแบบการส่งแล้วดูว่าข้อมูลหนึ่ง sample วิ่งผ่านชั้นไหนบ้าง ตั้งแต่ publish() ผ่าน rmw, middleware, kernel และ NIC จนถึง callback ฝั่งรับ ตัวเลขที่ติดป้าย “วัดจริง” มาจาก packet capture ในภาค 3 ของเอกสาร

ข้อมูลผู้ใช้ discovery / ควบคุม payload ใน GPU ถูกทิ้ง จุดที่ CPU copy payload ชั้นที่ไม่ได้ใช้ (จาง)

ทีละขั้น (ชี้เพื่อดูตำแหน่งในแผนภาพ)

    Packet จริงจาก capture (ชี้ที่แถวเพื่อดู byte)

    ข้อเท็จจริงของแบบนี้

    เทียบทุกแบบ (คลิกแถวเพื่อเปิด)

    แบบขอบเขตcopy ของ payloadผ่าน network stack ของ kerneltcpdump เห็นข้อมูลต้องตั้งค่าเพิ่ม

    ป้ายกำกับ: วัดจริง จาก pcap หรือตัวนับของ kernel ในภาค 3 · จากโค้ด อ่านจาก source ของ Lyrical · ประมาณการ คำนวณจากแบบจำลอง · ความรู้ทั่วไป ยังไม่ได้ตรวจกับ source ของเวอร์ชันนี้

    จำนวน copy นับเฉพาะ copy ของ payload ที่ CPU ทำ ไม่นับ DMA การทดลองข้ามเครื่องในภาค 3 ใช้ Docker container สองตัวต่อกันผ่าน veth จึงไม่ผ่าน NIC จริง ตำแหน่งของภาพที่หายในภาพเคลื่อนไหวเป็นตัวอย่าง ส่วนจำนวนที่หายเป็นค่าที่วัดได้

    ดูแบบ 3D พร้อม service และ action ได้ที่ Lyrical Packet Lab · เอกสาร: ros2_lyrical/ · packet ถอดจาก captures/*.pcap ด้วย tools/rtps_peek.py
