เส้นทางข้อมูล ROS 2 Lyrical

เทียบเส้นทางการส่งข้อมูล 10 แบบ ตั้งแต่เร็วที่สุด (ใน process เดียว) ไปจนถึงส่งข้ามเครื่อง ไล่ดูว่าข้อมูลหนึ่ง sample ผ่านชั้นไหน ถูก CPU copy กี่ครั้ง และดู packet จริงจาก capture ในภาค 3

ข้อมูลผู้ใช้ discovery / ควบคุม payload ใน GPU ถูกทิ้ง จุดที่ CPU copy payload ชั้นที่ไม่ได้ใช้ (จาง)

ทีละขั้น (ชี้หรือคลิกเพื่อดูตำแหน่งในแผนภาพ)

    ข้อเท็จจริงของแบบนี้

    Packet จริงจาก capture (ชี้ที่แถวหรือ byte เพื่อดูตำแหน่ง)

    เทียบทุกแบบ (คลิกแถวเพื่อเปิดดูรายละเอียด)

    แบบcopy ของ payloadผ่าน network stack ของ kerneltcpdump เห็นข้อมูลต้องตั้งค่าเพิ่มเหมาะกับ / ข้อสังเกต

    ป้ายกำกับความเชื่อมั่น: วัดจริง จาก pcap หรือตัวนับของ kernel ในภาค 3 · จากโค้ด อ่านจาก source ของ Lyrical · ประมาณการ คำนวณจากแบบจำลอง · ความรู้ทั่วไป ยังไม่ได้ตรวจกับ source ของเวอร์ชันนี้

    จำนวน copy นับเฉพาะ copy ของ payload ที่ CPU ทำ ไม่นับ DMA · การทดลองข้ามเครื่องในภาค 3 ใช้ Docker container สองตัวต่อกันผ่าน veth จึงไม่ผ่าน NIC จริง · ตำแหน่งภาพที่หายในภาพเคลื่อนไหวเป็นตัวอย่าง ส่วนจำนวนที่หายเป็นค่าที่วัดได้จริง

    ดูแบบ 3D พร้อม service และ action ได้ที่ Lyrical Packet Lab · เอกสาร: ros2_lyrical/ · ถอด packet จาก captures/*.pcap ด้วย tools/rtps_peek.py
